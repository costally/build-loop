## 1. 화면 목적

- 실제 선택 메뉴·훅의 사용 가능 여부와 설치 경계를 확인한다.
- Codex 앱·CLI 대화의 개념 목업이다. 별도 웹 UI 구현이나 호스트 내부 UI 변경을 확정하지 않는다.

## 2. 레이아웃 (텍스트 와이어프레임)

```text
+--------------------------------------------------------------+
| [1] 설치 위치
| [2] 환경 확인
| [3] 검사 결과
| [4] 기존 설정
| [5] 다음 작업
+--------------------------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<ConversationView>
  <Section1 /> {/* [1] 설치 위치; POL-002, POL-003, POL-009 */}
  <Section2 /> {/* [2] 환경 확인; POL-002, POL-003, POL-009 */}
  <Section3 /> {/* [3] 검사 결과; POL-002, POL-003, POL-009 */}
  <Section4 /> {/* [4] 기존 설정; POL-002, POL-003, POL-009 */}
  <Section5 /> {/* [5] 다음 작업; POL-002, POL-003, POL-009 */}
</ConversationView>
```

트리는 정보·동작 구분용이다. 실제 Codex 호스트 컴포넌트를 교체하는 구현 요구가 아니다.

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 단계별 자료 준비됨 | 구성 요소 1~5 표시. 예시 데이터임을 표시 |
| 로딩 | 조회·저장·검사 중 | 설치 경로와 지원 기능을 확인하고 있습니다. |
| 빈 상태 | 표시할 자료 없음 | 아직 확인한 환경이 없습니다. |
| 에러 | 정책 위반 또는 실패 | 기존 파일 또는 프로젝트 경계와 충돌합니다. 대상 경로를 확인해 주세요: {경로} |

목업 상단의 상태 선택은 검토 도구이며 제품 기능이 아니다. 비기본 상태에서는 주요 동작을 비활성화한다.

## 7. 인터랙션 상세

- 지원 확인 전 정상 시작으로 표시하지 않는다. 충돌·미지원이면 진행을 차단하고 필요한 조치를 제시한다. 이 목업 버튼은 실제 환경 검사 없이 다음 예시로 이동한다.
- 상단 앱/CLI 선택은 표현 예시만 바꾸며 기능 지원 통과를 의미하지 않는다.
- 비기본 상태에서는 주요 동작을 비활성화한다. 오류 복구는 POL-006을 따른다.
- 목업 내 클릭은 실제 파일·승인·프로젝트 상태를 변경하지 않는다.
