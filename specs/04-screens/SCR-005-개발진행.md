## 1. 화면 목적

- 현재 작업·요구 ID·변경·검증 결과와 다음 작업을 확인한다.
- Codex 앱·CLI 대화의 개념 목업이다. 별도 웹 UI 구현이나 호스트 내부 UI 변경을 확정하지 않는다.

## 2. 레이아웃 (텍스트 와이어프레임)

```text
+--------------------------------------------------------------+
| [1] 현재 단계
| [2] 현재 작업
| [3] 검증 결과
| [4] 진행 제어
| [5] 다음 작업
+--------------------------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<ConversationView>
  <Section1 /> {/* [1] 현재 단계; POL-004, POL-005, POL-006, POL-007 */}
  <Section2 /> {/* [2] 현재 작업; POL-004, POL-005, POL-006, POL-007 */}
  <Section3 /> {/* [3] 검증 결과; POL-004, POL-005, POL-006, POL-007 */}
  <Section4 /> {/* [4] 진행 제어; POL-004, POL-005, POL-006, POL-007 */}
  <Section5 /> {/* [5] 다음 작업; POL-004, POL-005, POL-006, POL-007 */}
</ConversationView>
```

트리는 정보·동작 구분용이다. 실제 Codex 호스트 컴포넌트를 교체하는 구현 요구가 아니다.

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 현재 단계 | 정보 | 예시: 개발·검증 반복 · 스펙 v1.0 · 상태는 실제 통과 결과가 아닙니다. | POL-004, POL-005, POL-006, POL-007 |
| 2 | 현재 작업 | 정보 | 예시 요구 ID → 변경 파일 → 인수 조건 → 실행 검증을 연결해 표시합니다. | POL-004, POL-005, POL-006, POL-007 |
| 3 | 검증 결과 | 정보 | 통과 1 / 실패 1 / 미실행 1 / 차단 0 (모두 목업 데이터) · 검증 대상 코드 버전 표시 현재 스펙·코드·환경 버전과 해당 검증의 실제 통과를 연결합니다. 오류 키·복구 주기를 보존합니다. | POL-004, POL-005, POL-006, POL-007 |
| 4 | 진행 제어 | 정보 | 스펙 내부 실패는 자동 복구합니다. 범위·주요 설계·완료 기준 변경은 사용자 판단을 요청합니다. 명시적 중단을 존중합니다. 실행·배포 준비 중 계정·권한·비용 판단이 필요하면 대상·범위·필요 조치만 요청하고 대기합니다. | POL-004, POL-005, POL-006, POL-007 |
| 5 | 다음 작업 | 동작 | 복구 흐름 또는 검증 완료 후 실제 시연으로 이동 | POL-004, POL-005, POL-006, POL-007 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 단계별 자료 준비됨 | 구성 요소 1~5 표시. 예시 데이터임을 표시 |
| 로딩 | 조회·저장·검사 중 | 현재 작업의 검증을 실행하고 있습니다. |
| 빈 상태 | 표시할 자료 없음 | 아직 실행한 검증이 없습니다. 미실행으로 표시합니다. |
| 에러 | 정책 위반 또는 실패 | 현재 결과물에 유효한 검증 또는 시연 확인이 부족합니다. 미확인 항목: {목록} |

목업 상단의 상태 선택은 검토 도구이며 제품 기능이 아니다. 비기본 상태에서는 주요 동작을 비활성화한다.

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 해당 없음 | - | 이 화면은 작업·증거 조회, 사용자 결정은 별도 질문 | 해당 없음 | POL-005 |

## 7. 인터랙션 상세

- 필수 실패·미실행을 남겨둔 채 완료 처리하지 않는다. 목업 링크는 별도의 통과 예시를 보여준다. 복구 필요 시 SCR-006으로 이동하고 질문 대기 상태에서는 자동 실행하지 않는다.
- 상단 앱/CLI 선택은 표현 예시만 바꾸며 기능 지원 통과를 의미하지 않는다.
- 비기본 상태에서는 주요 동작을 비활성화한다. 오류 복구는 POL-006을 따른다.
- 목업 내 클릭은 실제 파일·승인·프로젝트 상태를 변경하지 않는다.
