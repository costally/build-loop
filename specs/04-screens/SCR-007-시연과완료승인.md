## 1. 화면 목적

- 실제 결과물의 핵심 흐름을 확인하고 해당 버전의 완료 여부를 판단한다.
- Codex 앱·CLI 대화의 개념 목업이다. 별도 웹 UI 구현이나 호스트 내부 UI 변경을 확정하지 않는다.

## 2. 레이아웃 (텍스트 와이어프레임)

```text
+--------------------------------------------------------------+
| [1] 시연 대상
| [2] 사용 확인
| [3] 검증 근거
| [4] 사용자 판단
| [5] 다음 작업
+--------------------------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<ConversationView>
  <Section1 /> {/* [1] 시연 대상; POL-001, POL-007, POL-008, POL-009 */}
  <Section2 /> {/* [2] 사용 확인; POL-001, POL-007, POL-008, POL-009 */}
  <Section3 /> {/* [3] 검증 근거; POL-001, POL-007, POL-008, POL-009 */}
  <Section4 /> {/* [4] 사용자 판단; POL-001, POL-007, POL-008, POL-009 */}
  <Section5 /> {/* [5] 다음 작업; POL-001, POL-007, POL-008, POL-009 */}
</ConversationView>
```

트리는 정보·동작 구분용이다. 실제 Codex 호스트 컴포넌트를 교체하는 구현 요구가 아니다.

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 단계별 자료 준비됨 | 구성 요소 1~5 표시. 예시 데이터임을 표시 |
| 로딩 | 조회·저장·검사 중 | 시연 대상 버전과 검증 근거를 확인하고 있습니다. |
| 빈 상태 | 표시할 자료 없음 | 아직 시연할 결과물이 없습니다. |
| 에러 | 정책 위반 또는 실패 | 현재 결과물에 유효한 검증 또는 시연 확인이 부족합니다. 미확인 항목: {목록} |

목업 상단의 상태 선택은 검토 도구이며 제품 기능이 아니다. 비기본 상태에서는 주요 동작을 비활성화한다.

## 7. 인터랙션 상세

- 합의 범위의 실패는 SCR-005로 돌아가 수정·검증·재시연한다. 새 범위는 CR 및 다음 작업으로 연결한다. 승인 전 현재 상태는 사용자 확인 대기다. HTML 버튼은 문구만 바꾸며 실제 완료 기록은 생성하지 않는다.
- 상단 앱/CLI 선택은 표현 예시만 바꾸며 기능 지원 통과를 의미하지 않는다.
- 비기본 상태에서는 주요 동작을 비활성화한다. 오류 복구는 POL-006을 따른다.
- 목업 내 클릭은 실제 파일·승인·프로젝트 상태를 변경하지 않는다.
