## 1. 화면 목적

- 작업할 프로젝트와 실제 경로를 확인하고 신규 생성 또는 재개한다.
- Codex 앱·CLI 대화의 개념 목업이다. 별도 웹 UI 구현이나 호스트 내부 UI 변경을 확정하지 않는다.

## 2. 레이아웃 (텍스트 와이어프레임)

```text
+--------------------------------------------------------------+
| [1] 현재 작업 위치
| [2] 프로젝트 목록
| [3] 새 프로젝트
| [4] 재개 미리보기
| [5] 다음 작업
+--------------------------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<ConversationView>
  <Section1 /> {/* [1] 현재 작업 위치; POL-002, POL-004, POL-009 */}
  <Section2 /> {/* [2] 프로젝트 목록; POL-002, POL-004, POL-009 */}
  <Section3 /> {/* [3] 새 프로젝트; POL-002, POL-004, POL-009 */}
  <Section4 /> {/* [4] 재개 미리보기; POL-002, POL-004, POL-009 */}
  <Section5 /> {/* [5] 다음 작업; POL-002, POL-004, POL-009 */}
</ConversationView>
```

트리는 정보·동작 구분용이다. 실제 Codex 호스트 컴포넌트를 교체하는 구현 요구가 아니다.

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 현재 작업 위치 | 정보 | C:/build-loop/projects · 프로젝트 목록 예시 | POL-002, POL-004, POL-009 |
| 2 | 프로젝트 목록 | 정보 | 예시 프로젝트: idea-demo · 마지막 단계: 인터뷰 · 미응답 질문 1개 | POL-002, POL-004, POL-009 |
| 3 | 새 프로젝트 | 정보 | 영문 프로젝트명으로 docs/와 code/를 구성합니다. 이름·경로 충돌 시 기존 파일을 보존합니다. | POL-002, POL-004, POL-009 |
| 4 | 재개 미리보기 | 정보 | 확정 결정·현재 단계·첫 미완료 작업을 확인합니다. 저장 상태와 실제 파일이 다르면 먼저 차이를 표시합니다. 동일 DB의 revision과 실제 파일을 대조합니다. 낡은 revision은 거절하며 잠금 대기는 최대 5초입니다. | POL-002, POL-004, POL-009 |
| 5 | 다음 작업 | 동작 | 예시 프로젝트 선택 → 인터뷰 | POL-002, POL-004, POL-009 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 단계별 자료 준비됨 | 구성 요소 1~5 표시. 예시 데이터임을 표시 |
| 로딩 | 조회·저장·검사 중 | 프로젝트 상태를 불러오고 있습니다. |
| 빈 상태 | 표시할 자료 없음 | 아직 프로젝트가 없습니다. 새 프로젝트로 시작해 주세요. |
| 에러 | 정책 위반 또는 실패 | 저장 상태와 실제 파일이 다릅니다. 확인이 필요한 항목을 표시했습니다. |

목업 상단의 상태 선택은 검토 도구이며 제품 기능이 아니다. 비기본 상태에서는 주요 동작을 비활성화한다.

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 프로젝트명 | Y(신규) | 실제 경로 경계·중복·기존 파일 충돌 검사, 세부 이름 규칙 미정 | 기존 파일 또는 프로젝트 경계와 충돌합니다. 대상 경로를 확인해 주세요: {경로} | POL-002 |

## 7. 인터랙션 상세

- 신규·재개의 두 경로를 구분한다. 목업은 idea-demo 예시만 사용하며 파일을 생성하지 않는다. 실제 상태 불일치는 SCR-006의 복구 흐름으로 연결한다.
- 상단 앱/CLI 선택은 표현 예시만 바꾸며 기능 지원 통과를 의미하지 않는다.
- 비기본 상태에서는 주요 동작을 비활성화한다. 오류 복구는 POL-006을 따른다.
- 목업 내 클릭은 실제 파일·승인·프로젝트 상태를 변경하지 않는다.
