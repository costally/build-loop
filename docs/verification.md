# v0.2.0 검증 범위

## 다운로드 폴더에서 시작하는 세션 연결

루트 AGENTS.md가 사용자 아이디어와 본체 개발 요청을 구분한다. 루트 훅은 실제 session_id별 연결을 사용하며, `begin`이 다운로드 폴더의 `projects/<이름>`에 프로젝트를 생성하거나 명시적으로 지정한 프로젝트를 재개한다. 작업 디렉터리와 Codex 세션은 그대로 유지한다.

독립 임시 다운로드 폴더에서 실제 런처 → begin → 세션 연결 → 루트 훅 → 제어기 → 브리프 상태 조회를 검사한다. 기존 상태 보존, 다른 세션의 연결 분리, 승인 전 코드 쓰기·본체 수정 차단, 저장 질문과 메뉴 요청의 일치도 검사한다. 이는 실제 Codex 화면에서의 메뉴 표시나 전체 사용자 흐름을 대신하지 않는다. 훅의 정상 검토와 호스트 권한은 그대로 적용된다.

## 실행한 검사

- 생성된 실제 hooks.json 명령을 Windows에서 실행해 승인 전 코드 쓰기 deny, 현재 단계 문서 쓰기 허용, 단계 건너뛰기·프로젝트 밖 쓰기·지침 변경·임의 셸 거절을 검사했다.
- 실제 Windows PowerShell → control.py → SQLite → 검증 하위 프로세스 경로로 10문항 저장·재개, 단계별 확인, 스펙 승인, 구현 작업, 검증, 시연/완료 확인, 중단/재개, CR 반영을 연결했다.
- 위 통합 검사의 메뉴 전달은 명시적인 모의 세션이다. 실제 화면 렌더링·실제 사용자의 완료 승인을 대신하지 않는다.
- 결과 미확인·문서 변경·오래된 승인·수정 의견·실패 검증에서는 전환하지 않는다. 실제 실패 명령을 최초 1회 + 복구 3회 실행한 뒤 네 번째 복구를 거절했다. 통과 증거가 있을 때만 복구 주기를 해결 처리한다.
- 비화면 명세 검사와 CR의 파일 일괄 반영·구조 재검사·원본 보존을 검사했다. 동시에 쓰는 세션의 revision 충돌과 실제 5초 쓰기 잠금 한도를 검사한다.

## 성능 측정

Windows 11 / Python 3.13.15 / SQLite 3.50.4 / C: 로컬 저장에서 100개 프로젝트, 각 1,000개 사건으로 시작해 연산별 100회 측정했다. 정렬한 95번째 값을 사용했다. 상태 조회 p95 0.0092초 미만, 답 저장 0.0280초 미만, 재개 안내 0.0296초 미만이었다. 모델·네트워크·UI와 잠금 충돌은 이 수치에 포함하지 않았다. 다른 PC의 성능 보장은 아니다.

## 실제 호스트 확인과 필요한 최초 설정

설치된 터미널 실행 파일 0.170.0과 PC 앱 내장 실행 파일 0.171.0-alpha.13의 실제 App Server에서 초기 연결 및 hooks/list를 호출했다. 새 비신뢰 검사 프로젝트에서는 훅 목록이 비어 있었다. 이를 실제 강제 차단이나 전체 UI 통과로 기록하지 않았다.

[OpenAI 훅 규칙](https://learn.chatgpt.com/docs/hooks)에 따라 프로젝트와 새 훅은 정상 검토가 필요하다. 신뢰 우회 옵션·전역 trust 편집은 사용하지 않는다. 이 최초 사용자 설정 뒤 실제 두 화면에서 도구 거절·메뉴·전체 흐름을 관찰해야 한다.

```powershell
python tools/prepare_native_validation.py --root <비어있는검사루트>
```

이 명령은 검사 폴더와 사용자 실행용 Check-CLI.cmd만 만든다. 모델을 시작하지 않는다. CLI에서는 해당 CMD를 사용자가 실행하고 정상 프로젝트·/hooks 검토를 한다. PC 앱에서는 출력된 같은 프로젝트 폴더를 열고 RUN-IN-CODEX.md의 요청을 실행한다. 검사는 기획을 다시 시작하지 않으며, 단일 실제 코드 쓰기 거절과 파일 미생성 관찰을 기록한다. 단일 차단 검사만으로 전체 제품 완료를 선언하지 않는다.
