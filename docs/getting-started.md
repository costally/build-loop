# build-loop 처음 사용하기

이 설명서는 Windows에서 GitHub 코드를 처음 내려받아, Codex와 함께 **숫자 카운터 웹페이지**를 만드는 과정을 안내합니다. 터미널 명령은 PowerShell 기준입니다.

build-loop는 개발 순서와 승인 상태를 관리하는 도구입니다. 터미널에서 프로젝트를 만들고, 생성된 프로젝트를 Codex에서 열어 대화하며 작업합니다.

## 1. 준비하기

다음 프로그램이 필요합니다.

- Python 3.13 이상
- Git
- 로그인하여 사용할 수 있는 Codex PC 앱 또는 Codex CLI

PowerShell에서 아래 명령을 한 줄씩 실행합니다. 코드 블록 오른쪽의 복사 버튼을 사용해도 됩니다.

```powershell
python --version
git --version
```

Python은 `Python 3.13.x` 이상, Git은 버전 번호가 나오면 됩니다. 명령을 찾지 못하거나 Python 버전이 낮으면 해당 프로그램을 설치한 뒤 터미널을 다시 여세요. 별도 Python 패키지나 `.env` 파일은 필요하지 않습니다.

## 2. GitHub에서 다운로드하기

이미 GitHub에서 다운로드해 압축을 풀었다면 **3번으로 이동**하세요.

### ZIP으로 받기

1. https://github.com/costally/build-loop 에 접속합니다.
2. **Code → Download ZIP**을 누릅니다.
3. ZIP 파일을 우클릭해 **모두 압축 풀기**를 선택합니다.
4. 압축을 푼 폴더 안에서 `build-loop.cmd`와 `README.md`가 함께 있는 폴더를 찾습니다. ZIP 안에서 직접 실행하지 마세요.

### Git으로 받기

PowerShell에서 아래 명령을 실행해도 됩니다. `C:\build-loop-download`는 아직 없는 폴더여야 합니다. 이미 있다면 다른 새 폴더 이름을 쓰세요.

```powershell
git clone https://github.com/costally/build-loop.git C:\build-loop-download
cd C:\build-loop-download
```

다운로드한 도구 폴더는 계속 보관하세요. 생성되는 프로젝트가 이곳의 실행 파일을 참조합니다.

## 3. 다운로드 폴더에서 터미널 열기

파일 탐색기에서 **`build-loop.cmd`가 있는 폴더**를 엽니다. 주소 표시줄을 클릭하고 `powershell`을 입력한 뒤 Enter를 누르면 그 위치에서 터미널이 열립니다.

이미 터미널을 열었다면 아래 명령으로 위치를 확인하세요.

```powershell
Get-Item .\build-loop.cmd
.\build-loop.cmd --help
```

파일 정보와 명령 도움말이 나오면 준비됐습니다. `찾을 수 없습니다`가 나오면 `build-loop.cmd`가 있는 폴더에서 다시 터미널을 여세요.

## 4. 첫 테스트 프로젝트 만들기

이번 예제의 기능은 세 가지입니다.

- 처음 페이지를 열면 숫자 **0** 표시
- 버튼을 누를 때마다 **1씩 증가**
- 새로고침하면 **0으로 초기화**

아래 두 명령을 순서대로 실행합니다. 첫 명령은 프로젝트를 저장할 기본 폴더를 준비합니다. 기존 폴더의 내용은 유지됩니다.

```powershell
New-Item -ItemType Directory -Path C:\build-loop -Force
.\build-loop.cmd start --name counter-test --idea "버튼을 누를 때마다 숫자가 1씩 증가하는 웹페이지. 처음에는 0이고 새로고침하면 0으로 초기화."
```

오류 없이 생성되면 프로젝트 위치는 다음과 같습니다.

```text
C:\build-loop\projects\counter-test
```

이 명령은 **프로젝트 준비만** 합니다. 아직 웹페이지가 만들어지거나 Codex가 자동으로 시작되지는 않습니다. 별도 `install.ps1` 실행 없이 다운로드한 폴더에서 시작할 수 있습니다.

`counter-test`가 이미 있다는 오류가 나오면 기존 프로젝트를 이어서 열거나, 새 테스트는 명령의 이름을 `counter-test-2`로 바꾸세요. 기존 폴더를 삭제할 필요가 없습니다.

## 5. 생성된 프로젝트를 Codex에서 열기

### Codex PC 앱을 사용하는 경우

앱의 프로젝트/작업 폴더 선택 기능에서 아래 폴더를 엽니다.

```text
C:\build-loop\projects\counter-test
```

다운로드한 도구 폴더 대신 **방금 생성한 프로젝트 폴더**를 선택하세요. 이 폴더에는 `AGENTS.md`, `docs`, `code`가 있습니다.

### Codex CLI를 사용하는 경우

PowerShell에서 다음을 실행합니다.

```powershell
cd C:\build-loop\projects\counter-test
codex
```

### 첫 대화

Codex에 아래 문장을 보냅니다.

> 시작. build-loop 프로세스에 맞춰 숫자 카운터 예제를 진행해. 현재 저장된 상태를 확인하고 첫 미완료 단계부터 시작해.

프로젝트 신뢰나 훅 검토 안내가 나오면 내용을 검토하고 정상 절차로 허용하세요. 훅은 승인 전 구현이나 단계 밖 작업을 제어합니다. CLI에서는 `/hooks`로 훅 목록을 확인할 수 있습니다. 호스트 버전에 따라 표시 방식은 다를 수 있습니다.

훅이 보이지 않거나 로드에 실패하면 그 화면의 오류를 Codex에 알려주세요. 현재 배포본은 로컬 자동 검사를 통과했으며, 실제 PC 앱·CLI에서의 전체 동작은 사용자 테스트로 확인하는 단계입니다.

## 6. 질문과 문서를 확인하며 진행하기

다음 순서로 진행합니다.

```text
아이디어 인터뷰 → 브리프 → 요구사항(PRD) → 정책
→ 화면·동작 명세 → 테스트 계획(QA) → 전체 스펙 승인
→ 구현·검증 → 실제 실행 확인 → 최종 완료 승인
```

Codex가 질문하면 표시된 선택 메뉴에서 답하거나 의견을 입력하세요. 문서를 보여주면 원하는 기능인지 확인하고, 수정이 필요하면 구체적으로 말하세요. 예를 들어 `새로고침하면 반드시 0으로 돌아가야 해`처럼 답하면 됩니다.

**추천 선택, 개별 문서 확인, 전체 스펙 승인, 최종 완료 승인은 각각 별도입니다.** 실제로 표시되는 확인 메뉴나 안내된 확인 문구를 사용하세요. 답 없이 메뉴를 닫으면 결정이 확정되지 않습니다. 메뉴가 표시되지 않으면 Codex에 그 사실을 알려주세요.

기획이 끝나고 전체 스펙을 승인하면 구현을 진행합니다. 생성 파일의 위치는 다음과 같습니다.

| 위치 | 내용 |
|---|---|
| `docs` | 기획 문서, 요구사항, 화면·동작 설명, 테스트 계획 |
| `code` | 실제 웹페이지 등 결과물 |
| `.build-loop` | 재개에 필요한 로컬 상태와 실행 기록 |

## 7. 완성된 카운터 직접 테스트하기

Codex가 안내한 실행 방법으로 웹페이지를 엽니다. 실행 방법은 구현 결과에 따라 안내받으세요.

1. 페이지를 처음 열었을 때 **0**인지 확인합니다.
2. 버튼을 한 번 누르면 **1**인지 확인합니다.
3. 한 번 더 누르면 **2**인지 확인합니다.
4. 브라우저를 새로고침하면 **0**인지 확인합니다.

다르면 실제 동작을 알려 수정 요청을 하세요. 예: `두 번 눌렀는데 3이 나와. 한 번에 1씩만 증가하도록 수정해.`

원하는 대로 동작하면 시연 확인과 별도로 표시되는 **최종 완료 승인**까지 진행합니다. 자동 테스트 통과만으로 사용자 확인을 대신하지 않습니다.

## 8. 중단했다가 이어서 하기

작업을 멈추려면 Codex에 `중단해`라고 요청하고 진행 상태를 확인하세요. 다시 시작할 때는 **같은 프로젝트 폴더**를 열고 다음처럼 요청합니다.

> 이어서 진행해. 저장된 상태를 확인하고 첫 미완료 작업부터 재개해.

이미 만든 프로젝트에 `start` 명령을 다시 실행하지 마세요. `.build-loop` 폴더를 포함한 프로젝트 전체를 보관해야 기존 상태를 이어갈 수 있습니다.

## 자주 막히는 곳

| 상황 | 할 일 |
|---|---|
| `build-loop.cmd`를 찾지 못함 | 파일이 실제로 있는 다운로드 폴더에서 PowerShell을 열기 |
| `python` 또는 `git` 명령을 찾지 못함 | 필요한 프로그램 설치 후 터미널 다시 열기 |
| `C:\build-loop` 경로가 없다는 오류 | 4번의 `New-Item` 명령 실행 후 재시도 |
| 프로젝트 이름이 이미 존재함 | 기존 프로젝트를 열어 재개하거나 새 이름 사용 |
| 프로젝트만 생기고 개발이 시작되지 않음 | 생성된 프로젝트를 Codex에서 열고 5번의 첫 대화 보내기 |
| 훅·메뉴·승인 단계에서 멈춤 | 현재 오류와 화면에 나온 문구를 Codex에 전달하기 |

문제 보고 시에는 **어느 단계인지, 입력한 명령, 오류 문구**를 함께 전달하면 됩니다.
