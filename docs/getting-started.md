# build-loop 처음 사용하기

GitHub에서 내려받은 폴더에서 Codex를 열고, 만들고 싶은 것을 말하세요. **같은 폴더·같은 대화에서 질문, 기획, 승인, 구현, 테스트까지 진행합니다.** 프로젝트 생성 명령을 외우거나 다른 폴더로 옮길 필요가 없습니다.

## 1. 준비하기

Windows에서 Python 3.13 이상, Git, 로그인한 Codex CLI 또는 PC 앱이 필요합니다. 추가 Python 패키지와 `.env` 파일은 필요하지 않습니다.

PowerShell에서 확인할 수 있습니다.

```powershell
python --version
git --version
```

명령을 찾지 못하면 해당 프로그램 설치 후 터미널을 다시 여세요.

## 2. 다운로드하기

[GitHub 저장소](https://github.com/costally/build-loop)에서 **Code → Download ZIP**을 선택하고 **모두 압축 풀기**를 실행합니다. `README.md`, `AGENTS.md`, `build-loop.cmd`가 함께 있는 폴더가 시작 폴더입니다. ZIP 안에서 직접 실행하지 마세요.

Git을 사용한다면 아래처럼 받을 수 있습니다. 목적지 폴더는 아직 없는 새 경로를 사용하세요.

```powershell
git clone https://github.com/costally/build-loop.git C:\build-loop-download
```

## 3. 그 폴더에서 Codex 열기

파일 탐색기로 다운로드 폴더를 열고 주소 표시줄에 `powershell`을 입력한 뒤 Enter를 누릅니다. 그 터미널에서 다음을 실행합니다.

```powershell
codex
```

Codex PC 앱을 사용하면 다운로드한 폴더 자체를 작업 폴더로 선택하세요.

프로젝트 신뢰와 훅 검토가 표시되면 내용을 검토하고 정상 절차로 허용합니다. 이 폴더에 포함된 훅이 현재 세션과 프로젝트를 연결합니다. 정상 권한 요청이 나오면 요청한 명령을 확인하세요. Full Access로 바꾸는 것은 필수 단계가 아닙니다.

## 4. 만들고 싶은 것을 말하기

첫 대화는 다음처럼 쓰면 됩니다.

> 웹페이지 메모장 만들자.

가장 작은 예제로 시험하려면 다음처럼 요청하세요.

> 버튼을 누르면 숫자가 1씩 증가하는 웹페이지 만들자. 처음에는 0이고 새로고침하면 0으로 초기화해.

Codex는 다운로드 폴더 안의 `projects/<이름>/`에 작업 자료를 만들고, **지금 대화에서** 첫 미완료 작업을 진행합니다. 첫 질문은 실제 선택 메뉴로 표시하며, 이미 말한 내용은 다시 묻지 않습니다. 단순한 아이디어라면 필요한 확인 후 브리프 작성으로 이어질 수 있습니다.

별도의 `start` 명령, `install.ps1` 실행, 프로젝트 폴더 다시 열기, Codex 재실행은 필요하지 않습니다. 시작을 위해 본체 내부 코드를 분석하거나 사용자가 프로젝트 경로를 관리할 필요도 없습니다.

## 5. 질문과 문서를 확인하기

진행 순서는 다음과 같습니다.

```text
인터뷰 → 브리프 → 요구사항(PRD) → 정책 → 화면·동작
→ 테스트 계획(QA) → 전체 스펙 승인 → 구현·검증
→ 실제 실행 확인 → 최종 완료 승인
```

질문 메뉴에 답하고, 문서를 보여주면 원하는 내용인지 확인하세요. 다르면 `새로고침해도 메모가 남아야 해`처럼 수정할 내용을 말합니다. 빈 응답은 결정으로 처리하지 않습니다.

추천 선택, 개별 문서 확인, 전체 스펙 승인, 최종 완료 승인은 별도입니다. 표시된 확인 메뉴나 안내된 확인 문구를 사용하세요. 승인한 범위를 바꾸고 싶다면 대화에서 변경 내용을 요청하세요.

## 6. 실제 결과 확인하기

구현 후 Codex가 안내하는 방법으로 결과물을 실행합니다. 카운터 예제라면 다음을 확인하세요.

1. 처음 열면 **0**
2. 한 번 누르면 **1**
3. 한 번 더 누르면 **2**
4. 새로고침하면 **0**

다르면 관찰한 동작을 말해 수정 요청을 하세요. 원하는 대로 작동하면 시연 확인 후 최종 완료 승인까지 진행합니다. 자동 테스트 통과만으로 사용자 확인을 대신하지 않습니다.

## 7. 중단과 재개

작업을 멈추려면 `중단해`라고 요청합니다. 같은 대화에서 다시 작업할 때는 다음처럼 말하세요.

> 저장된 상태에서 이어서 진행해.

새 대화라면 같은 다운로드 폴더에서 Codex를 열고 프로젝트 이름을 알려주세요.

> web-notepad 프로젝트를 이어서 진행해.

새 세션은 명시적으로 지정한 기존 프로젝트에 연결합니다. 이전 답과 문서·구현 상태를 보존하며, 중단 상태라면 재개 확인을 받습니다. 프로젝트 이름이 불분명하면 한 번 확인합니다.

## 파일은 어디에 있나요?

```text
다운로드한 폴더/
  AGENTS.md, build-loop.cmd 등    시작 지침과 도구
  .build-loop/                   세션별 프로젝트 연결 (Git 제외)
  projects/<이름>/
    docs/                        기획·요구사항·테스트 계획
    code/                        실제 결과물
    .build-loop/                 저장 상태·실행 기록 (Git 제외)
```

폴더 전체를 보관하세요. 기존 버전에서 `C:\build-loop\projects`에 만든 프로젝트는 그대로 보존됩니다. 새 흐름의 기본 위치는 다운로드 폴더 안의 `projects`입니다.

## 막혔을 때

| 상황 | 할 일 |
|---|---|
| `codex` 명령이 없음 | Codex CLI 설치 상태를 확인하거나 PC 앱에서 다운로드 폴더 열기 |
| Python 실행 오류 | 오류 문구를 전달하기. Python이 없다고 단정해 재설치하지 않기 |
| 질문 JSON만 출력되고 메뉴가 없음 | `저장한 질문을 실제 선택 메뉴로 표시해`라고 요청하기 |
| 폴더 이동이나 프로젝트 재생성을 요구함 | 최신 다운로드인지 확인하고 현재 폴더·세션에서 계속 진행하도록 요청하기 |
| 훅이 로드되지 않음 | 정상 프로젝트·훅 검토 상태와 표시된 오류 확인 |

오류를 보고할 때는 요청한 문장과 Codex 응답·오류 문구를 함께 전달해 주세요. 로컬 자동 검사와 실제 Codex 화면 검증은 구분하며, 현재 호스트의 실제 동작은 사용자 테스트로 확인합니다.
